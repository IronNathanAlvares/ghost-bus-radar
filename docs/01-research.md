## 1. The problem is real and unmeasured

- Ghost buses are buses shown on real-time displays that never arrive. The NTA attributes them to
  operators cancelling too late for the real-time system to pick it up.
  [Dublin Inquirer](https://www.dublininquirer.com/please-exorcise-ghost-buses-from-dublin-bus-real-time-information-services-passengers-say/),
  [Irish Times, Feb 2025](https://www.irishtimes.com/ireland/dublin/2025/02/12/issue-of-ghost-buses-on-agenda-for-ministers-first-meeting-with-national-transport-authority)
- Dublin Bus has claimed real-time accuracy of about 98 to 99 per cent, and its CEO has said the
  existing system (in place since 2010) is "not quite real time".
  [Newstalk](https://newstalk.com/news/the-end-of-ghost-buses-dublin-bus-real-time-system-being-replaced-within-three-years-1755958)
- The only public measurement is a crowdsourced no-show tracker, whose data quality the NTA has
  questioned. [Dublin Inquirer](https://www.dublininquirer.com/routes-introduced-under-busconnects-among-most-often-reported-on-no-show-bus-tracker/)
- A new national AVL system (Trapeze) was contracted; reports in 2026 mention a pilot starting in
  September. **[verify]** current status in S7.
  [Newstalk](https://newstalk.com/news/will-new-location-system-end-the-haunt-of-ghost-buses-1768794),
  [Greystones Guide](https://www.greystonesguide.ie/whitmore-suggests-follow-that-bus-tracking/)

## 2. NTA feeds

- v2 endpoints: `https://api.nationaltransport.ie/gtfsr/v2/TripUpdates` and `/Vehicles`, key sent in
  the `x-api-key` header, keys from developer.nationaltransport.ie (Azure API Management portal).
  [Transitland](https://www.transit.land/feeds/f-national~transport~authority~ie~rt),
  [NTA upgrade notice](https://www.nationaltransport.ie/attention-developers-upgrade-to-gtfs-realtime-api)
- v2 adds Luas and Irish Rail to the real-time updates. Same NTA notice.
- Community projects report about one TripUpdates call per 60 s per key and Vehicles at 30 s or
  slower; `?format=json` reportedly works. **[verify]** in S1 by measurement.
  [4NextDart](https://github.com/ZarleyLtd/4NextDart), [Dublin-Bus-Live](https://github.com/JeetankNaidu/Dublin-Bus-Live),
  [GTFS-V2-Home-Assistant](https://github.com/CDeLeon94/GTFS-V2-Home-Assistant)
- Static GTFS: `https://www.transportforireland.ie/transitData/Data/GTFS_Realtime.zip` (realtime
  operators) among others, CC BY 4.0, "updated regularly".
  [TFI PT Data](https://www.transportforireland.ie/transitData/PT_Data.html)
- Realtime must be used with the static schedule of the same version; IDs "can change between
  data generations" and static updates may be daily. NTA upgrade notice above.
- From the NTA GTFS v2 platform update PDF (January 2023, published by the NTA; a local copy is kept
  in `research/sources/` and not republished here):
  - `route_id` and `trip_id` are autogenerated, numeric, and **not persistent** across schedule
    uploads; route number can no longer be parsed from them.
  - `stop_id` is the NaPTAN AtcoCode; new `stop_code` is the plate code.
  - `agency_timezone` is `Europe/London`; Go-Ahead split into three agencies; Bus Éireann and
    Expressway merged.
  - `stop_headsign` populated only for the first stop.
- Usage policy for realtime data: page exists at developer.nationaltransport.ie/usagepolicy but
  was not readable without sign-in. **[verify]** in S1 before publishing anything.

### 2a. First look at the real static feed (downloaded 15 November 2026)

`GTFS_Realtime.zip`, which the NTA developer portal names as the static file to use with GTFS-R.
Unzipped it is 586 MB, mostly `stop_times.txt` (391 MB, 7.43 M rows) and `shapes.txt` (195 MB).

| Observation | Design impact |
|---|---|
| `feed_info.feed_version` is a UUID (`14FEE109-…`), feed valid 2026-11-14 to 2027-11-14 | Use it as the SCD2 version key (ADR-0002) |
| 7 agencies: Dublin Bus `1`, Bus Éireann `2`, Go-Ahead `3` **and** `03C`, Bus Éireann Waterford `WFRD`, LUAS `10000`, Irish Rail `IR` | Route key uses `agency_id`, not agency name |
| `route_id` looks like `03C_120_e_a`, `10000_GREEN_g_a`; `trip_id` like `5858_1`. Not numeric as the 2023 PDF described | Still treated as opaque, per NTA's guidance |
| 401 routes: 116 Dublin Bus, 196 Bus Éireann, 62 Go-Ahead, 19 Irish Rail, 2 Luas, 5 Waterford | Scope sizing |
| 190,466 trips; 217,875 stop-time rows at or after 24:00:00 | Service-day logic is not an edge case |
| `agency_timezone` is `Europe/London` for every agency | Normalise to `Europe/Dublin` |
| `trips.txt` has `block_id` and `trip_short_name` populated | `block_id` may help detect a vehicle chaining trips |
| `translations.txt` has Irish stop names | Bilingual stop names on the website |

The NTA developer portal (pasted by the user) also lists a service alerts endpoint,
`https://api.nationaltransport.ie/gtfsr/v2/alerts`, notes the API is throttled under its fair-usage
policy, and says a new subscription can take 15 minutes to activate.

## 3. Lessons from people who archive GTFS-RT at scale

[Kurt Raschke, "GTFS-realtime at scale"](https://kurtraschke.com/2025/10/gtfs-realtime-at-scale):
fetch errors range from under 0.1% to 5% depending on the producer (404 races, protobuf parse
failures, timeouts), retries handle low rates, and some producers emit invalid protobuf. Design
consequence: retry with jitter, store failures in a DLQ, never let one bad snapshot stop the poller.

## 5. Exactly-once with Iceberg

Checked in the Iceberg source (`SparkWrite.java`, Spark 3.5 module): the streaming sink's
`commit(epochId, …)` walks the snapshot history for this query's `spark.sql.streaming.queryId`,
reads the stored `spark.sql.streaming.epochId`, and skips any epoch already committed. So plain
streaming appends into Iceberg are idempotent across restarts. `foreachBatch` writes do not get
this for free; they need deterministic `MERGE` keys and our own batch-id bookkeeping.
[Iceberg source](https://github.com/apache/iceberg/blob/main/spark/v3.5/spark/src/main/java/org/apache/iceberg/spark/source/SparkWrite.java)
